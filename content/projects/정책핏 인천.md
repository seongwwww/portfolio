# 정책핏 인천

> 인천시 청년 일자리 정책 사이의 **지원 공백 · 인계 공백 · 조정 필요 중복 · 의도적 병행 · 보완 관계**를 규칙으로 판정해, 공무원이 신규사업 검토 3단계에서 쓰는 「유사·중복 사업 자체 검토서」 초안을 만들어 주는 도구.

🏅 **인천대·울산대 초광역 AI 해커톤 장려** · 팀 F4 · 주제 I3

---

## 💡 아이디어 — 어디서 시작했나

배정받은 주제는 **"청년 인재 유출 및 지역 산업·정책 연계 부족"** 이었다.

주제를 그대로 읽으면 답은 정해져 있다 — **청년-기업 매칭 플랫폼**. 대부분의 팀이 거기로 간다. 여기서 멈추지 않은 게 이 프로젝트의 출발점이다.

데이터를 먼저 봤다.

| 통념 | 확인된 사실 |
|---|---|
| 청년이 인천을 떠난다 | **주소 기준으로는 순유입** (2025년 순유입률 1.1%, 전국 1위) |
| 그래서 붙잡아야 한다 | 실제로는 **인천에 살면서 관외로 출근**한다 (32.8%) |
| 매칭이 부족해서다 | 이유 1위는 "원하는 직무의 일자리가 없어서" |

여기서 결론이 뒤집혔다. **청년의 선택을 좌우하는 건 임금·기업규모·직무다양성·경력전망이고, 소프트웨어가 이걸 직접 바꿀 수는 없다.**

## 🔍 도출 과정 — 어떻게 여기까지 왔나

### 재정의 — 바꿀 수 없는 것 대신 바꿀 수 있는 것

> **"임금과 직무는 소프트웨어가 못 바꾼다. 대신 정책 결정의 품질은 바꿀 수 있다."**

I3의 두 축 중 **'산업·정책 연계 부족'을 직접 타겟**으로 잡았다 ([[#D-001]]). 성과 귀속을 4단계로 쪼개고, **뒤 2단계(양질의 일자리 → 청년 정착)는 우리 플랫폼에 귀속시키지 않는다**고 명시했다 (D-002). 과대 주장을 스스로 차단한 결정이다.

근거도 붙였다 — 제2차 청년정책 기본계획 69개 사업 중 **계속·확대가 85.5%**, 교육·훈련 분야는 92.3%. 실제로 벌어지는 일은 신규 신설이 아니라 **기존사업 조정**이다.

동시에 한계도 못 박았다: *"이건 인천 청년정책 포트폴리오 한정 수치다. '지자체 세출 대부분이 계속사업'이라는 전국 명제로 말하지 않는다."*

### 남은 공백을 찾았다

선행 서비스를 조사한 결론 한 문장:

> **기존 도구는 전부 정책을 *찾아주는* 도구다. 정책을 *만드는 사람*을 위한 도구는 확인되지 않았다.**

### 해결 원리

각 사업을 `문제 → 대상 → 수단 → 시기 → 예산 → KPI` 공통 카드로 정규화하고, 카드들 사이에서 **공백 / 역할중첩 / 인계단절 / 시차**를 규칙으로 탐지한다.

**AI가 하는 일과 하지 않는 일을 화면에 노출했다.** LLM 금지 목록 — 출처 없는 사실 보완 / 정합성 점수 직접 생성 / 사업폐지·예산삭감 자동결정.

### ② 정답셋이 틀렸다는 걸 발견했다 — 그리고 점수가 나빠지는 쪽으로 고쳤다
정답셋 16건을 31건으로 늘렸는데(D-017), **판별력 결함**을 발견했다. 쉬운 케이스만 있어서 뭘 넣어도 통과하는 정답셋이었다.
양성 통제군을 추가하고 프롬프트를 v7까지 밀었다 — **지표가 나빠지는 방향의 갱신**이었다. (D-018)

> 자기 점수를 깎는 방향으로 평가 기준을 고친 결정. 면접에서 쓸 수 있는 가장 강한 일화.

### ③ 화면에서 산업 3개가 사라졌는데, 원인이 우리였다
로봇·항공·미래차가 결과에서 빠졌다. 조사가 부족해서라고 생각했는데 **원인은 우리가 건 필터**였다. (D-029)
직접 수요 조사를 수행해 증거원장을 **29행 → 78행**으로 늘렸고(D-030), **공급·모수 지표가 수요로 둔갑하던 판정 버그**를 막았다(D-031).

### ④ 그래프 DB를 기각했다가 번복했다
D-009에서 "그래프는 모델로 채택, 그래프 DB는 기각"으로 정했는데, D-010에서 **Neo4j 실제 설치로 뒤집었다.** 대신 연결 실패 시 동일 논리의 파이썬 `MemoryStore`로 자동 전환되게 만들어 번복 비용을 없앴다.

### ⑤ 디자인 외주를 발주하려다 직접 만들었다
웹 프론트를 Stitch AI에 맡기기로 하고 화면 5개 발주서까지 고정했다가(D-039), **발주하지 않고 직접 Next.js로 구현**했다(D-040). 판정 로직은 옮기지 않았다.

## ⚖️ 설계 결정과 근거

### 판정은 규칙이, 추출만 LLM이
앱 README에 그대로 써 있다 — **"판정은 전부 규칙이 한다. LLM은 정책 원문을 카드로 정규화하는 추출 단계에만 존재한다 (`engine/detect.py`에 `import openai`가 없다)."**

| 이유 | 설명 |
|---|---|
| 설명 책임 | 공무원이 결재에 올리는 문서다. "왜 중복인가"에 답할 수 없으면 못 쓴다 |
| 채점 가능성 | `gold_set.csv` 정답셋으로 4지표를 뽑는다. 비결정적이면 채점 자체가 성립 안 함 |
| LLM은 2차 심판 | `judge2_pass.csv` — 판정자가 아니라 **검증자**로 한 단계 물렸다 |

### 기권 계약 (D-019)
**원문에 없는 필드는 반드시 `null` + `missing_fields`.** 추측으로 채우지 않는다. 환각을 계약으로 막았다.

### 모델 이원화 (D-021)
배치는 `gpt-4o-mini`, 라이브 시연만 `gpt-4o`. 비용과 품질을 용도별로 분리.

### 시연 실패를 3중으로 방어 (D-020)
| 터지는 것 | 대비 |
|---|---|
| Neo4j 연결 실패 | 파이썬 `MemoryStore` 자동 전환, 현재 스토어를 사이드바에 표시 |
| API 키 없음 | 카드가 이미 `data/cards/`에 추출·저장돼 있어 앱은 그대로 뜸 |
| 인터넷·앱 전부 불가 | `engine.snapshot` → `demo_fallback.html`, 의존성 없이 4화면 핵심 |
