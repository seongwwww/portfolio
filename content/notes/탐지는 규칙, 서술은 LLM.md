# 탐지는 규칙, 서술은 LLM

> 내 프로젝트를 관통하는 가장 중요한 원칙.

**판정처럼 검증 가능해야 하는 일은 규칙과 통계로, 서술처럼 사람 말이 필요한 일은 LLM으로 나눈다.**

## 왜

| 이유 | 설명 |
|---|---|
| **설명 책임** | "왜 이렇게 판정했나"에 답할 수 없으면 쓸 수 없는 곳이 있다 |
| **채점 가능성** | 정답셋으로 지표를 뽑으려면 결정론적이어야 한다. 비결정적이면 채점 자체가 성립하지 않는다 |
| **비용** | 규칙·통계는 무료다. LLM 호출은 정말 필요한 지점에만 |
| **환각 차단** | LLM이 판정하면 "그럴듯한 오답"이 섞인다. 규칙은 틀려도 재현 가능하게 틀린다 |

## 어디에 적용했나

### [[정책핏 인천]]
앱 README에 그대로 써 있다 — *"판정은 전부 규칙이 한다. LLM은 정책 원문을 카드로 정규화하는 추출 단계에만 존재한다 (`engine/detect.py`에 `import openai`가 없다)."*

LLM을 아예 뺀 게 아니라 **한 단계 물렸다.** `judge2_pass.csv` — 판정자가 아니라 **2차 검증자**로 배치.

### [[실은 silen]]
`.claude/rules/ai-evals.md` 첫 줄이 규칙이다 — *"핵심: 탐지=통계, 서술=LLM."*

차이 검출은 정보이론의 **surprisal**로 계산한다. `-log2(p)`, Jeffreys 평활, 활성 기록일 기준. LLM은 검출된 차이를 **문장으로 옮기는 일만** 한다.

### [[Focus Orbit]]
추천을 규칙 기반으로. 2일짜리 프로젝트에서 학습 기반은 데이터가 없어 시연 자체가 불가능했다.

## 반대편 — LLM에 맡긴 것

- **[[정책핏 인천]]** — 정책 원문에서 필드 추출(정규화). 다만 [[기권 계약]]을 걸었다
- **[[실은 silen]]** — 차이를 사람 말로 서술. 가드레일 + eval로 검증
- **[[Nextify]]** — 코드 변환의 애매한 판단. 단, 결과를 diff로 사람이 승인 ([[AI 결과물을 사람이 검토하게 만들기]])
